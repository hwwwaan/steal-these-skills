## 바로 시작하기

**핵심 가치:** 필요한 공부량이 가용 시간을 넘을 때도 부족분을 숨기지 않고, 학습 배정·예비 시간·미배정 시간을 나누어 오늘 할 일을 보여 줍니다.

**복사해서 시작:** “사회복지정책론 시험이 9월 25일 오후 2시야. 범위는 1~6장이고 8시간 필요해. 23일과 24일에는 각각 2시간 가능해. 예비 시간을 분리하고 저장 전 미리보기만 보여줘.”

## 실행 방법

1. Notion AI 채팅을 연다.
2. 입력창에 `/`를 입력하고 **벼락치기** 스킬을 선택한다.
3. 과목, 시험일, 범위, 공부 가능한 시간을 평소 말하듯 입력한다.
4. 먼저 계획 미리보기를 확인한다.
5. 공부 블록에 저장하려면 **추가** 또는 **반영**이라고 답한다.
6. 계획이 밀리면 **“완료하지 못한 블록만 오늘 이후로 다시 배정해줘”**라고 요청한다.

> 💬 **입력 예시**
> 사회복지정책론 시험이 12일 뒤야. 범위는 1~6장이고 총 8시간 필요해. 평일에는 30분, 주말에는 1시간 가능해.

## 꼭 입력할 정보

- 과목과 시험 일시
- 시험 범위
- 실제 공부 가능한 날짜와 시간

알고 있다면 필요 공부 시간, 현재 준비도, 시험 형식, 보유 자료, 다른 시험·과제 일정도 함께 입력한다. 누락값이 있어도 멈추지 말고 꼭 필요한 질문만 최대 3개 한 뒤, 가정을 밝힌 잠정 계획을 만든다.

상대 날짜가 입력되면 정확한 시험 날짜와 시간을 계산해 먼저 보여 준다. 시험 시간이 없으면 임의로 정하지 않고 **⚠️ 확인 필요**로 표시한다. 가능하면 계획 전에 기출 또는 대표 문제 5~10개로 짧은 진단을 제안하고 결과를 **개념 부족 / 유형 연습 필요 / 실수 교정 필요**로 분류한다.

## 핵심 계획 규칙

- 사용자가 입력한 시험일, 범위, 필요 시간과 일정을 임의로 바꾸지 않는다.
- 확인된 값과 가정을 명확히 구분한다.
- 시간이 부족해도 공부량을 임의로 줄이지 않는다. **필요 시간, 배정 시간, 미배정 시간**을 각각 표시한다.
- 기본 계획은 시험 전날까지 배치한다. 사용자가 시험 당일 계획을 명시적으로 요청한 경우에만 시험 시각과 이동·준비 여유를 확인한 뒤 시험 시작 전 범위에 배치한다. 시험 시각이나 여유 시간이 없으면 당일 시각을 임의로 만들지 말고 ⚠️ 확인 필요로 남긴다.
- 기본 계획은 시험 전날에 최종 점검 30분을 우선 확보하되, 확인된 가용 시간을 넘기지 않는다. 당일 계획을 명시 요청했으면 시험 시작 전 실제 가용 시간 안에 점검을 배치하고, 지난 전날에 새 블록을 만들지 않는다. 30분 확보가 어려우면 부족분을 알린다.
- 기존 계획과 지난 블록은 승인 없이 삭제하거나 덮어쓰지 않는다.
- 불명확한 값은 추측하지 말고 **⚠️ 확인 필요**로 남긴다.

## 작업 모드와 계산 방식

### 다일 계획 모드

시험까지 4일 이상 남았거나 날짜별 계획을 요청하면 사용한다.

- 오늘부터 시험 전날까지 공부 가능한 날짜를 펼친다.
- 요일별 가능 시간과 공부할 수 없는 날, 다른 시험·과제, 고정 일정을 반영한다.
- 기본 계획 단위는 30분 블록으로 한다. 필요한 경우에만 길이를 조정하고 이유를 표시한다.
- 앞으로 가능한 시간의 10~20%를 예비 시간으로 남긴다. 이미 완료한 학습 시간은 예비 시간 계산에서 제외하고, 남은 날짜 안에서 밀린 블록이나 취약 범위를 보완할 여유를 확보한다.
- 범위를 개념 학습, 능동 회상, 문제 풀이, 오답 보완, 최종 점검으로 나눈다.

### 긴급 벼락치기 모드

시험까지 3일 이하이거나 전날 계획을 요청하면 사용한다. 당일 계획은 사용자가 명시적으로 요청하고 시험 시각과 이동·준비 여유가 확인된 경우에만 시험 시작 전 범위에서 사용한다.

- 수면, 식사, 이동, 준비 시간을 제외해 실제 학습 가능 시간을 계산한다.
- 범위를 **최우선 / 우선 / 여유 시**로 분류한다.
- 25~50분 집중 블록과 5~10분 휴식을 사용한다.
- 읽기보다 능동 회상, 기출 풀이, 백지 복습, 말로 설명하기를 우선한다.
- 밤샘을 기본값으로 제안하지 않고 최소 수면을 확보한다.

### 계산 순서

1. 기본은 현재 날짜부터 시험 전날까지의 날짜를 생성한다. 당일 계획을 명시 요청한 경우에만 확인된 시험 시각과 이동·준비 여유를 제외한 시험 시작 전 시간을 포함한다.
2. 날짜별 가능 시간에서 고정 일정과 필수 생활 시간을 제외한다.
3. 범위와 필요 시간을 구체적인 공부 블록으로 나눈다.
4. 기출 빈도, 교수자의 강조, 학습목표, 과제·퀴즈를 근거로 우선순위를 정한다.
5. 하루 가능 시간을 넘지 않도록 우선순위가 높은 블록부터 배치한다.
6. 과목별로 완료 시간, 남은 필요 시간, 앞으로 가능한 시간, 새 학습 배정, 예비 시간, 가용 미사용 시간, 미배정 시간을 각각 계산한다.
7. 날짜별 합계와 전체 블록 합계를 다시 확인한다.

## 시험 유형별 학습법

- **수학·계산형:** 개념 확인 → 대표 예제 → 유형별 문제 → 시간 제한 실전 풀이 → 오답 재풀이 → 공식·조건 회상
- **암기형:** 질문-답 카드 → 묶음화 → 반복 회상
- **서술형:** 예상 질문 → 답안 구조 → 핵심 키워드 회상
- **객관식·단답형:** 개념 구분 → 기출 반복 유형 → 혼동 항목 회상
- 수학은 단순 문제 수보다 **도움 없이 풀이 과정을 재현할 수 있는가**를 완료 기준으로 삼는다.
- 오답은 **개념 부족 / 접근법 선택 실패 / 계산 실수 / 시간 부족**으로 분류하고 반드시 다시 푼다.
- ‘공부하기’ 대신 ‘3장 핵심 개념 10개를 백지에 재현’처럼 측정 가능한 완료 기준을 쓴다.

## 결과 출력 형식

### 가정

- 확인된 입력값
- 하루 또는 요일별 공부 가능 시간
- 범위를 시간으로 환산한 기준
- 잠정적으로 가정한 값과 이유

### 날짜별 시험 공부 계획

| 날짜 | 요일 | 과목 | 범위 또는 공부 블록 | 방법 | 공부 시간 | 하루 합계 / 가능 시간 |
| --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |

긴급 모드에서는 날짜 대신 실제 시각을 사용한다.

### 합계 점검

| 과목 | 필요 시간 | 실제 배정 시간 | 미배정 시간 |
| --- | --- | --- | --- |
|  |  |  |  |
- 총 필요 시간 = 완료 시간 + 새 학습 배정 + 미배정 시간
- 앞으로 가능한 시간 = 새 학습 배정 + 예비 시간 + 가용 미사용 시간
- 예비 시간과 가용 미사용 시간은 학습 배정이나 미배정 시간에 중복 포함하지 않는다.

### ⚠️ 확인 필요

- 불명확한 시험일, 범위, 필요 시간
- 다른 일정과 충돌하는 블록
- 사용자가 선택해야 하는 미배정 공부량

### 블록별 완료 기준

각 공부 블록에 범위, 학습 방법, 문제 수 또는 분량, 완료 기준, 실패 시 재학습 방법을 함께 표시한다. 예: `미분 활용 1~3유형 / 기본 5문제·응용 3문제 / 도움 없이 80% 이상 풀이 / 미달 시 오답 원인 기록 후 다음 날 재풀이`.

### 지금 바로 할 일

5분 안에 시작할 수 있는 첫 행동 하나를 굵게 제시한다.

## 공부 블록 저장 규칙

미리보기 단계에서는 데이터베이스를 변경하지 않는다. 다음처럼 저장 승인을 요청한다.

> 이 계획을 공부 블록에 저장하려면 **추가** 또는 **반영**이라고 답해 주세요. 수정할 내용이 있으면 먼저 알려 주세요.
> 

사용자가 저장 의사를 명확히 표현한 경우에만 실행한다.

1. ‣ 데이터베이스를 불러와 실제 속성 이름과 유형을 확인한다.
2. ‣ 데이터베이스에서 해당 시험 행을 확인한다.
3. 접근할 수 없거나 시험 행을 식별할 수 없으면 저장을 중단하고 **⚠️ 확인 필요**로 알린다. 속성이나 관계를 추측하지 않는다.
4. 각 계획 블록을 별도 행으로 저장한다.
    - 제목: 과목과 범위가 드러나는 이름
    - 날짜: 실제 공부할 날짜
    - 시간: 해당 블록의 공부 시간
    - 시험 연결: 과목 행이 아니라 **과제 데이터베이스의 해당 시험 행**
    - 상태: 시작 전
    - 완료 여부: 완료로 표시하지 않음
5. 저장된 시간 합계가 승인된 미리보기와 일치하는지 검수한다.

## 밀린 계획 다시 짜기

1. 완료되지 않은 지난 블록을 확인한다.
2. 지난 블록을 즉시 삭제하지 않는다.
3. 오늘 이후의 남은 공부 가능 시간만 다시 계산한다.
4. 옮길 수 있는 블록과 미배정으로 남을 블록을 구분한다.
5. 기존 날짜와 제안 새 날짜를 함께 보여 준다.
6. 사용자 승인 전에는 기존 데이터를 변경하지 않는다.
7. 승인 후에만 날짜나 상태를 수정하고 변경 전후를 검수한다.

## 연계 흐름

1. **학기시작:** 강의계획서에서 과목, 평가 비중, 시험·과제 일정과 원문 근거를 정리한다.
2. **공지정리:** 시험 공지에서 과목, 시험일, 범위, 준비물, 첫 행동과 원문 근거를 정리한다.
3. **벼락치기:** 남은 날짜와 가능 시간을 계산해 계획 미리보기를 만든다.
4. 사용자 승인 후 공부 블록으로 저장한다.
5. 계획이 밀리면 완료되지 않은 블록만 다시 배정한다.

연계 스킬이나 데이터베이스에 접근할 수 없으면 사용자가 제공한 정보로 미리보기까지 진행하고 저장 작업만 보류한다.

## 최종 검수 목록

- 상대 날짜를 정확한 시험 날짜로 변환해 확인했는가?
- 기본 계획은 오늘부터 시험 전날 사이인가? 당일 계획은 사용자가 명시 요청했고 시험 시각과 이동·준비 여유가 확인됐는가?
- 시험 시작 시각 이후나 이동·준비 시간에 공부 블록이 없는가? 요청하지 않은 당일 블록이나 과거 날짜의 신규 블록을 만들지 않았는가?
- 날짜별 합계가 가능 시간을 넘지 않는가?
- 총 필요 시간 = 완료 시간 + 새 학습 배정 + 미배정 시간인가?
- 앞으로 가능한 시간 = 새 학습 배정 + 예비 시간 + 가용 미사용 시간이고, 날짜별 학습·예비·미사용 합계와도 각각 일치하는가?
- 앞으로 가능한 시간의 10~20%가 예비 시간으로 확보됐는가? 이미 완료한 학습 시간은 앞으로 가능한 시간과 예비 시간 계산에 포함하지 않았는가?
- 휴식, 식사, 이동, 수면이 현실적으로 반영됐는가?
- 진단 결과와 오답 원인이 계획에 반영됐는가?
- 각 블록에 구체적인 완료 기준과 실패 시 대응이 있는가?
- 가정과 실제 입력값이 구분되어 있는가?
- 저장 전 사용자 승인을 받았는가?
- 공부 블록이 과목이 아닌 과제 데이터베이스의 시험 행에 연결됐는가?
- 기존 데이터가 승인 없이 삭제되거나 덮어쓰이지 않았는가?

## 추가 요청 예시

- “내일 오전 10시 경제학 시험이야. 2장까지만 봤고 오늘 6시간 가능해. 기출 중심으로 짜줘.”
- “3일 뒤 전공 시험 두 개가 겹쳐. 과목별 우선순위와 시간표를 짜줘.”
- “어제 공부를 못 했어. 완료하지 못한 블록만 오늘 이후로 다시 배정해줘.”

## 보완 전·후 비교

| 항목 | 보완 전 | 보완 후 |
| --- | --- | --- |
| 시험일 처리 | ‘10일 뒤’ 같은 상대 날짜를 그대로 사용 | 정확한 날짜·시간으로 변환하고 확인 |
| 준비도 판단 | 사용자의 주관적 설명 중심 | 대표 문제 5~10개 진단 결과 반영 |
| 수학 학습법 | 계산형 공통 규칙만 적용 | 개념→예제→유형→실전→오답 재풀이 구조 |
| 오답 관리 | 오답 원인 분류가 단순함 | 개념·접근법·계산·시간 부족으로 분류 |
| 일정 안정성 | 가능한 시간에 블록을 최대한 배치 | 전체 시간의 10~20%를 예비 시간으로 확보 |
| 완료 기준 | 학습 시간과 일반적인 행동 중심 | 문제 수·정답률·풀이 재현 여부까지 확인 |
| 계획 수정 | 미완료 블록을 이후로 재배정 | 진단과 실패 원인을 반영해 재배정 |

### 적용 후 사용 흐름

**시험 정보 입력 → 정확한 날짜 확인 → 간단한 실력 진단 → 날짜별 계획 생성 → 블록별 완료 기준 확인 → 미리보기 승인 → 공부 블록 저장 → 중간 점검 및 재배정**
